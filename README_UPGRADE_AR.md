# المروة — حزمة إصلاح واجهة الإدارة (تجريبية)

## التغييرات
- توحيد طلبات واجهة الإدارة من خلال `apiFetch` لإرسال Bearer token المحفوظ في sessionStorage.
- فحص حالة HTTP والاستجابة لكل تعديل/حذف/إضافة عبر API وإظهار الخطأ عند رفض الخادم، بدل المتابعة وكأن العملية نجحت.
- الإبقاء على حظر تسجيل العملاء والطلبات العامة لحين بناء مصادقة مستقلة محمية، وعدم إتاحة قائمة العملاء للمتصفح العام.
- الاحتفاظ بتجهيزات الداش بورد والتصميم وواجهة PDF/WhatsApp الموجودة في حزمة المراجعة السابقة.

## تحذيرات قبل النشر
هذه نسخة مراجعة **لا ترفع إلى main ولا تستخدم مع العملاء بعد**. يلزم اختبار تشغيل API والوظيفة `marwa_mutate_resource` مع قاعدة تجريبية أولًا. لم يُثبت نجاح بناء واجهة React هنا؛ تعذر إكمال تثبيت الاعتمادات في بيئة المراجعة. لم نطبق SQL ولم نغير Supabase أو GitHub أو Vercel.

- لا ترفع `.env.local` أو مفتاح `service_role` أو `api/db.json`.
- نسخ GitHub الاحتياطية لا تنسخ قاعدة بيانات Supabase. صدّر نسخة احتياطية من قاعدة البيانات قبل أي ترحيل SQL.
- تسجيل العميل الآمن يحتاج قاعدة بيانات بكلمات مرور مجزأة وجلسات، والأوردرات تتحقق من العميل والأسعار في الخادم.
- واجهة واتساب اليدوية ليست بوت WhatsApp Business API حقيقيًا حتى يتم ربط Meta وإعداد webhook.
- اختبر عمليات الرفض وفقد الجلسة والرفع والحذف قبل النشر.
