# المروة: حالة التطوير والاختبار

## تم تعديل هذا الإصدار
- توحيد طلب حفظ وتعديل الموظفين مع `apiFetch` المحمي بالجلسة بدل `fetch` الخام، حتى يظهر الخطأ ولا يحدث نجاح وهمي.
- إزالة متغيرات كلمة مرور الموظف غير المستخدمة من مسار حذف الفولدر (التحقق من صلاحية المدير يتم على API).
- الاحتفاظ ببيانات المشروع وعدم إرفاق أسرار أو قاعدة البيانات في الحزمة.

## قبل النشر
1. النسخة للاختبار فقط: تسجيل العملاء وطلباتهم **معطّلان**. لا تعتبرها نظامًا مكتملًا.
2. يجب ضبط SUPABASE_URL و SUPABASE_SERVICE_KEY في Vercel Server Environment، وعدم وضع Service Key في web أو GitHub.
3. يجب تثبيت دالة `sql/marwa_mutate_resource.sql` في قاعدة الاختبار **بعد النسخ الاحتياطي**، ووجود صف `app_data` برقم 1 ودخول مدير في `admin_users`.
4. تنبيه: الإجراء SQL مخصص لتعديل موارد المدير، ولا يحقق تلقائيًا هوية العملاء أو صحة أسعار الأوردرات.
5. اختبر البناء بـ `cd web && npm ci && npm run build` قبل النشر.
6. لا ترفع `api/db.json` أو `.env.local` إلى مستودع عام.
7. بوت WhatsApp Business API غير مربوط؛ زر واتساب داخل الطلبات هو تواصل يدوي فقط.

## خطوات اختبارات واجهة المدير
- الدخول إلى لوحة المدير ثم طلب بيانات `/api/categories` عبر المتصفح: يجب أن تكون JSON array.
- إضافة تصنيف تجريبي، تحديثه من لوحة التحكم والتأكد من بقائه بعد إعادة تحميل الصفحة.
- إنشاء منتج تجريبي وبحثه في المعرض.
- إنشاء أوردر تجريبي من المدير فقط حيث الوظيفة متاحة ثم تجربة تغيير الحالة والحفظ.
- مراجعة صلاحيات المدير وانتهاء صلاحية الجلسة.

الموقع الأصلي لم يُعدَّل، ولا يوجد في هذا الأرشيف إثبات لنجاح الربط ببيانات Supabase الفعلية.
